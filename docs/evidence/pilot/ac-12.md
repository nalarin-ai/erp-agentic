## Explicit assumptions

These assumptions bound every AC result in this pilot. They are recorded here so the sign-off owner can judge whether each still holds at go-live.

1. **Fixture adapters, not live ERPNext.** All provider I/O went through `FixtureErpAdapter` / `FixtureCrmAdapter`. No live ERPNext pilot, credential, migration, or destructive action was touched. The real contract surfaces (workflows, authz, settings, reports) are production code; the *transport* is a fixture.
2. **Synthetic opaque references only.** Every identifier (`ACTOR-*`, `UNIT-*`, `CUST-*`, `ACC-*`, `ISSUER-*`, `TAX-*`, …) is a synthetic alias. No real customer, account number, or secret appears in any test or fixture.
3. **Harness code-map workaround (underscore catalog codes).** The production `_unit_code_for_ref` derives refs as `UNIT-{code}`, which cannot represent underscore catalog codes (`HEAVY_EQUIPMENT`, `PT_TKH_OPS`) through the authz canonical-ref grammar `[A-Z0-9-]`. The harness binds an explicit code↔ref map (`_PilotDraftWorkflow._CODE_BY_REF`). This is a **harness-side workaround for a latent source limitation** — see finding F-a and ac-02.md.
4. **In-memory settings store.** `UnitSettingsStore` is the in-memory fixture; durable persistence plugs into the same CAS contract. Lifecycle (draft→activate→rollback) and fail-closed validation are production behavior; the *store backend* is not.
5. **Headless-domain UX.** There is no browser harness in this repo; UI is represented as pure view-model builders (`ui/invoice_review/*`, `ui/receivables/*`). AC-11 therefore proves the *view-model contract the DOM binds to* (layout mode, tab order, roles, accessible names, recovery copy, no-overflow flag), not pixel rendering. Browser/independent review remains an open EXP-001 item.
6. **Deterministic synthetic clock.** All flows anchor at `T0 = 2026-08-14T00:00Z` via `at(minutes)`. Time-based behavior (settings effective windows, assignment revisions) is exercised deterministically.
7. **Pre-existing integration failures are out of scope.** The full suite carries 2 pre-existing FAILs in `tests/integration` (`test_export_is_scope_bounded_with_evidence`, `test_payment_evidence_index`). They predate this pilot, are unrelated to the pilot ACs, and were deliberately NOT touched (owned-paths constraint).
