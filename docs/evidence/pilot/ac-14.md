# MVP-AC-14 — multi-unit user selects exactly one authorized active unit

- Criteria: a user holding several unit assignments must select exactly one authorized active unit per request; unassigned/expired/revoked selection is denied; cross-unit data never leaks; stale cache/preview after assignment or settings change cannot be posted; report/export surfaces are scope-bounded per unit. (FND-002, CRM-001, FLOW-001/002, RPT-001, UX-001.)

## How the tests prove it

Suite: `tests/e2e/pilot/test_ac_14_multi_unit.py` (9 tests; harness wires the real authz engine, workflows, CRM adapter, and AR aging read model over fixtures).

1. **Positive one-context-per-request:** the multi-unit reviewer (FINANCE-REVIEWER on BANYUMEDIA + CONTRACTOR) reads the AR report in EACH unit; every request selects exactly one unit and every returned entry belongs to that unit only.
2. **Ambiguity denied:** with several active assignments and no explicit selection, `authorize` returns `UNIT_CONTEXT_REQUIRED` and the denied decision discloses no unit_ref.
3. **Unassigned selection denied:** selecting PT_TKH (not assigned) → `PERMISSION_DENIED`, generic message, no echo of the requested ref, denial audited on the report surface.
4. **Revoked CRM roster denied live:** removing the actor from the CRM roster immediately denies `read_lead` (roster is read live by the fixture adapter — no stale cache).
5. **Revoked authz assignment denied:** flipping the assignment to inactive denies the report query (`PERMISSION_DENIED`).
6. **Cross-unit leak denied:** a BYM-only reviewer asking for CONTRACTOR rows → `PERMISSION_DENIED`; the server-derived scope intersection never widens.
7. **Stale preview after settings change cannot be posted:** a preview rendered at config vN is blocked (`STALE_PREVIEW`, zero provider mutation) once the active version moves on — audited.
8. **Stale assignment revision denied:** a request pinning an old assignment revision against a bumped (revoked+re-issued) assignment → `STALE_PREVIEW`, no unit disclosed.
9. **Report/export scope-bounded per unit:** per-unit queries return only that unit's rows with `scoped=True`; an unfiltered query spans ONLY the authorized units, never a foreign unit (PT_TKH absent), and per-unit totals are never merged.
