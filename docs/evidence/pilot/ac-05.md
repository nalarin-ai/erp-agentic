# MVP-AC-05 — retry never duplicates

- Criteria: stale worker / lost response retries never duplicate drafts, official numbers, provider writes, or AR applications; blind retry is blocked until reconciliation classifies the uncertain outcome.

## How the tests prove it

Suite: `tests/e2e/pilot/test_ac_05_retry.py` (6 tests; assertions inspect real workflow audit events and the fixture adapter provider-call counts — no mocks of the system under test).

1. `open_draft` replayed with the same idempotency key returns the SAME draft id (no duplicate draft, no extra audit mutation).
2. Same idempotency key with a DIFFERENT payload → `IDEMPOTENCY_CONFLICT` denial.
3. Post retried after a lost success response never issues a second official number (single `PostedInvoiceRecord`, single provider write).
4. Blind re-post while the first outcome is UNCERTAIN → `WorkflowBlocked(INVALID_STATE)` until `reconcile_post` classifies; after classification the safe retry succeeds exactly once.
5. Payment retried with the same `evidence_ref` replays without a second provider write and without double-applying to AR.
6. Blind payment retry while classification is pending → blocked until `reconcile_payment` completes (REC-001 fencing).
