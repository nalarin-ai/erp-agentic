# MVP-AC-10 — export/backup/isolated restore

- Criteria: the OPS-001 tooling produces a complete manifest with valid checksums from synthetic fixture stores; an isolated restore verifies; corrupt/missing/inconsistent sets are rejected; pilot/live mode refuses without the explicit acknowledgement flag.

## How the tests prove it

Suite: `tests/e2e/pilot/test_ac_10_backup_restore.py` (9 tests; real subprocess invocations of `python3 -m scripts.backup.backup_run` / `restore_verify` against a synthetic fixture root in a tmp dir — no live containers touched).

1. Fixture-mode backup produces a manifest covering all `REQUIRED_STORES` with valid sha256 checksums.
2. `restore_verify` into an isolated target directory succeeds and reconciles artifacts.
3. Missing manifest → rejected (non-zero exit).
4. Corrupt manifest JSON → rejected.
5. Tampered artifact (checksum mismatch) → rejected.
6. Manifest missing a required store → invalid at load time.
7. Missing fixture store → backup fails with NO partial manifest left behind.
8. Pilot mode without the acknowledgement flag → refused.
9. Pilot mode with live containers absent → refused (skipped when the pilot db container is up — guard verified in OPS-001 suite; skip is by-design).
