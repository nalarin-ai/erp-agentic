# MVP-AC-11 — compact/wide/a11y/recovery UX (UX-001)

- Criteria: gateway surfaces render truthful view-models for compact and wide viewports, expose keyboard/focus semantics as data, keep recovery copy for blocked/denied states safe (zero disclosure), and never allow field overflow.

## Scope note (headless-domain)

This repository has no browser harness; UI is represented as pure view-model builders (`ui/invoice_review/view.py`, `ui/invoice_review/unit_selector.py`, `ui/receivables/view.py`) fed by the REAL workflow surfaces (`render_for_review`, CRM-backed assignments, AR aging report). These tests therefore prove the **contract the browser binds to** over real pilot data — layout mode, table/list representation, tab order, control roles, accessible names, focus semantics, and recovery copy — not pixel rendering. Browser/independent review remains an open EXP-001 item (see ac-12.md).

## How the tests prove it

Suite: `tests/e2e/pilot/test_ac_11_ux.py` (13 tests).

1. `render_for_review` payload → review view-model: compact variant uses `labeled_cards`, wide uses `columns`, and **both** carry `horizontal_overflow=False`.
2. Every rendered compact line stays within the 120-char budget — no physical line overflow.
3. Hostile long free-text (500-char customer display) still leaves the compact variant with no horizontal overflow; identity fields are never truncated.
4. Tab order mirrors the EXACT footer actions authorized for the actor (F-05): a poster gets `action_post` but not `action_return`; a reviewer the reverse; every action tab stop has a role + Indonesian accessible name; cancel is always last.
5. Post-confirmation dialog focus contract: focus enters the heading, is contained, returns to the trigger.
6. Denied view is generic (`Anda tidak memiliki akses…`), names the escalation path, and echoes neither unit nor customer ref (zero disclosure).
7. Error state preserves review context (draft_id, unit_ref, error_code) and names a recovery action.
8. Post-result states are truthful: no false "posted and verified"; REJECTED → "failed without mutation" + "Perbaiki dan coba lagi"; UNCERTAIN → "reconciliation required" + "Jangan ulangi" + reconciliation ref; raw provider detail never leaks.
9. Real stale-preview blocker (`WorkflowBlocked` on version conflict) maps to a safe recovery state, and the blocker message carries no protected refs.
10. Unit selector states READY / SELECT_REQUIRED / EMPTY / REVOKED / STALE each carry safe recovery copy; a foreign current-unit ref yields STALE without echoing its label.
11. Switch-confirmation names its effects (`clear_scoped_results`, `invalidate_preview_hash`, `reload_options`) and warns about unsaved changes; a non-member target is denied without disclosure.
12. Receivables view locks the unit filter to the authorized unit (single-unit actor), marks the result `scoped`, and offers compact/wide variants + a11y contract + denied/offline recovery states.
13. Receivables a11y contract: tab order includes the table, roles and Indonesian accessible names are present, focus visible.
